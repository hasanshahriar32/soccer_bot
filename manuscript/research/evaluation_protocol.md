# HazBot evaluation protocol

Active study, 21 October 2026. This supersedes the previous ball-pursuit replay protocol, preserved in the dated archive. The paper evaluates source-derived geometry, isolated command semantics, and a new abstract reference coordinator. The author-reported ball-based control simulation is task context, not a measured physical benchmark or a physics simulation generated by these experiments.

## Reproduce

Run from the repository root:

```bash
python3 manuscript/experiments/characterize_hazbot.py
python3 manuscript/experiments/verify_hazbot_mission.py
python3 manuscript/scripts/build_figures.py
bash manuscript/compile.sh
python3 manuscript/scripts/check_submission.py
python3 manuscript/scripts/package_sources.py
```

Both analyses require only Python's standard library. They do not instantiate ROS, open sockets/serial devices, load detector weights, or actuate motors. Use --output-dir to compare regenerated artifacts without overwriting current outputs. The reference verifier also regenerates its TeX summary from computed values.

## Geometry

Input: scripts/robot.urdf. Select base yaw, shoulder pitch and elbow pitch with the exact declared origins/axes/limits; fixed wrist origin is the endpoint. The shoulder is at (0.100,0,0.155) m and each positioning link is 0.100 m. Zero coordinates form a right angle, not a collinear chain.

An analytic FK and an independent generic homogeneous chain are compared over 1,000 seeded random poses and 13 special poses. Maximum disagreement is 6.8e-17 m, interpreted as numerical agreement. The link sum gives an analytical 0.200 m bound. A 41×41×41 joint grid includes declared bounds, produces 68,921 poses, and retains the 2,747 samples below modeled ground. Sagittal plotting selects all 1,681 zero-yaw poses; 67 have negative z.

The endpoint is not a calibrated contact TCP. No self-collision, ground collision, torque, payload, cable, dynamics, compliance, stability or grasp feasibility model is applied. Counts do not represent uniform Cartesian volume or probability.

## Source command semantics

The exact wheel gateway SET branch is AST-isolated. The transport sender becomes a list recorder; runtime module imports and startup code are bypassed. Execute all integer inputs -255..255 for both wheels: 511² = 261,121 pairs. Compare outputs against a separately defined sign partition. F/B/L/R each receive 65,025 inputs, exactly one pair emits S, and 1,020 mixed-zero pairs emit no new command. This does not establish motor movement or stopping.

The arm mapper is pure source-isolated code. Evaluate B/S/A/E/G aliases for 451 inputs -90..360, giving 2,255 cases; E aliases the elbow A and is not a fifth actuator. Compare clamps/reversals against an independent implementation. The gateway conventions are not measured physical angles.

Geometry, schema extraction, wheel semantics, arm mapping and source invariants comprise 29 passing characterization checks. Source/dataset hashes and exact settings are in hazbot_characterization.json; independent read-back is in hazbot_characterization_validation.json.

## Reference coordination

New artifact: experiments/verify_hazbot_mission.py. It is a discrete reference specification, not an existing deployed autonomous controller. Seven phases: SEARCH, APPROACH, DOCK, GRASP, CARRY, PLACE, COMPLETE. Twelve external Boolean observations yield 4,096 valuations. No consistency pruning is applied, so some combinations may be physically impossible.

All 7×4,096 = 28,672 phase/observation pairs are checked for each of four policies (114,688 total). An explicit separate oracle checks issued command obligations and command-to-phase contracts. Base motion requires fresh usable scan, clear route and stowed arm. Advance also needs an authorized fresh target. Arm actions require stopped base; reach/close need authorized fresh reachable target; transport needs grip; release needs deposit zone and grip. The controller has additional conservative scan gates during arm phases that are not separate oracle obligations.

Policies remove only the named guard group: base–arm interlock, target authorization, or scan age. Full policy: zero violations. Ablations: 480, 128, 288 violating pairs. Shortest counterexample observation prefixes: 1, 2, 1 from SEARCH. Counters are domain cardinalities, never probabilities or physical failure rates.

BFS explores phase transitions under arbitrary next observations. Each policy reaches all seven phases, has 13 unique phase edges including self-loops, and has shortest completion depth 6. An independent hand-constructed 11-step Boolean witness covers all nine action types and completes. This is existential abstract progress, not guaranteed physical success.

HOLD is an abstract actuation inhibit. Blocked guards preserve phase; acquisition and completion may advance logical phase while emitting HOLD. Hardware needs explicit stop, cancellation, arbitration and feedback semantics. Inputs such as stopped-base, grip, release, authorization and reachability are assumed facts here. The oracle does not prove all transition correctness, physical safety, sensing validity or hazard containment.

The model runs 109 checks. Data, source bindings, counterexamples and validation records are in hazbot_mission_*.json/csv; the paper table is generated/hazbot_mission_summary.tex. See hazbot_mission_method.md for exact predicates, independent cube counts and witnesses.

## Reporting boundary

Three evidence classes remain distinct in prose and captions: source inspection/execution, ideal geometry, and bounded reference-model analysis. No recognition accuracy, physical latency, payload, endurance, physical obstacle-avoidance score, or hazardous-material trial is claimed. Conflicting proposed hardware and unsubstantiated slide figures are documented in hazbot_evidence_assessment.md and are not merged into result tables. Legacy replay data remain historical supplementary software analysis.
